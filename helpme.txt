Для работы с HTTP-запросами и OAuth 2.0
В PyCharm можно настроить аутентификацию для HTTP-запросов с использованием OAuth 2.0. Для этого нужно:
    В файле с расширением  .http
    в списке Run with выбрать окружение, к которому будет добавляться конфигурация аутентификации.
    В панели инструментов нажать Add → Auth Configuration. Это добавит шаблон конфигурации аутентификации в публичный
    файл окружения в объект Auth под Security выбранного окружения.
    Заменить placeholder
    auth-id
    на осмысленное имя, которое будет использоваться для ссылки на эту конфигурацию в
    .http
    -файле.
    Указать параметры аутентификации. Они зависят от выбранного Grant Type. При заполнении параметров можно
    использовать помощь PyCharm: начинать ввод имени параметра или нажимать
    Ctrl+Space
    для списка доступных JSON-ключей.
    Использовать переменную
    {{$auth.token()}}
    , передав ей имя конфигурации аутентификации (например,
    {{$auth.token("my-config")}}
    ). Эту переменную можно применять в заголовке авторизации запроса или в параметрах запроса.
    Нажать Run для отправки запроса. Перед доступом к защищённому ресурсу HTTP Client отправит запрос на сервер
    авторизации для получения токена доступа. При появлении запроса нужно завершить процесс аутентификации.

Для работы с GitHub
Чтобы использовать токен для аутентификации в PyCharm при работе с GitHub, нужно:
    Сгенерировать персональный токен доступа (Personal Access Token) в настройках аккаунта GitHub:
    Settings → Developer settings → Personal access tokens → Generate new token.
    Указать название токена, выбрать срок действия и при необходимости добавить разрешения
    (например, для репозитория, workflow, gist).
    В настройках PyCharm перейти в раздел GitHub и добавить новые учётные данные, введя сгенерированный токен вместо
    обычного имени пользователя и пароля.
 stackoverflow.com
Важно сохранить сгенерированный токен, так как после закрытия страницы он станет недоступен. github.com


<<ПРИВЯЗКА ЛОКАЛЬНОГО РЕПОЗИТОРИЯ К GitHUB>>

1) Подготовьте локальный репозиторий. Если вы ещё не работали с Git, установите его на компьютер.
2) Затем в папке с вашим проектом выполните команду git init — она создаст скрытый каталог .git,
   где будет храниться история изменений. После этого добавьте файлы в индекс и сделайте коммит:
   git add . и git commit -m "Ваше сообщение"
3) Создайте пустой репоз-рий на GitHub. Войдите в свой аккаунт и нажмите «+» в правом верхнем углу → «New repository».
4) Придумайте имя, при желании добавьте описание, выберите видимость (Public — для всех, Private — только для вас).
   Не ставьте галочку «Initialize this repository with a README», если вы уже создали файл README.md локально — иначе
   возникнет конфликт. Нажмите «Create repository».
5) Свяжите локальный репозиторий с удалённым.
   На странице только что созданного репозитория скопируйте URL. Вам нужен вариант с .git в конце (например,
   https://github.com/ваше_имя_пользователя/имя_репозитория.git).
   В терминале перейдите в папку с вашим проектом и выполните команду:
   git remote add origin https://github.com/ваше_имя_пользователя/имя_репозитория.git
   Здесь origin — это имя, которое вы даёте удалённому репозиторию в вашем локальном проекте
6) Отправьте изменения. Выполните: git push -u origin main
   Флаг -u устанавливает связь между локальной и удалённой ветками — в будущем для отправки туда и обратно
   достаточно будет просто git push.
   Если у вас по умолчанию используется другая ветка (не main), замените main на её имя.

Несколько советов, чтобы избежать проблем
    Аутентификация. При использовании HTTPS Git может запросить аутентификацию.
    Если вы используете личный токен доступа (а не пароль), это решит вопрос.
    SSH. Если вы предпочитаете SSH, убедитесь, что SSH-ключ добавлен в настройки аккаунта GitHub.
    Иначе при попытке отправки через SSH возникнет ошибка Permission denied (publickey)
    Конфликты. Если при следующей отправке вы получите конфликт (например, кто-то другой изменил ту же ветку),
    разрешите его локально, а затем выполните git push --force (но используйте эту опцию с осторожностью)
